# RPG Maker MV/MZ desktop plugins

MV/MZ use `GAME_SAVE`: native storage is imported before `SceneManager.run` begins engine boot. The bridge does not invoke `DataManager.saveGame`, invoke `DataManager.loadGame`, allocate a reserved save slot, change scenes, or clear plugin-specific caches. Plugins build their normal startup state from the imported native directory, and players load through the game itself.

The native bridge supplies a limited `require('fs')` before plugins execute, so plugins can capture the module at script scope. File operations become available when the native channel connects. It does not expose Node, `process`, other modules, host paths, or network URLs. Read methods are `existsSync`, `readdirSync`, and `readFileSync`; relative `./` paths and absolute paths within the game's virtual directory resolve to the same content. Text encoding is UTF-8; unencoded reads return bytes with UTF-8 `toString()`.

Before starting MV or MZ, the adapter reads scenario `.sl`/`.txt` files and `.talk`/`.txt`/`.csv`/`.json` data below `js/plugins/` through managed Content I/O, in chunks of at most 256 KiB. The synchronous read set is limited to 4,096 files and 16 MiB total. MV scenario scripts beside `www/` remain included without exposing desktop executables or sibling projects. Plugin data is relative to the entry directory. Engine JSON, images and audio retain demand loading. These text assets remain immutable and use the existing Content I/O persistent cache; they are not copied into checkpoints.

MV also supports `mkdirSync`, `writeFileSync` and `unlinkSync`, restricted to direct `save/*.rpgsave` files, at most 128 files and 16 MiB total. `StorageManager.localFileDirectoryPath()` names this virtual directory without changing MV's browser storage mode. Shared plugin files are independent `FILESYSTEM` entries in the native save bundle. They are imported with the browser storage before engine boot. Every ordinary native slot, global index, configuration value and supported shared file is included in a synchronization export. MZ's `fs` surface is read-only; its native saves continue through localforage with the existing checkpoint format.

Shared files belong to the selected Retrom native save bundle. Restoring an older bundle restores its shared files too; a new game does not inherit shared state from a different run. This does not implement an independent, always-latest achievement or unlock store. Save metadata and identity checks stay owned by the game's original engine and plugins.

This is a bounded compatibility surface, not a general NW.js implementation. Unsupported modules, encodings, paths, and oversized file sets fail explicitly. No game scripts, source archives, database schema, or host API need changing.
